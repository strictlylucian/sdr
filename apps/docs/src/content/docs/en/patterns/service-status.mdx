## Service unavailable

Return HTTP 503 where appropriate. Explain the issue, any evidence-based recovery time and alternative channels. Do not invent a restoration estimate.

<Preview name="ServiceUnavailable" locale="en" />

<Tabs>

Separate a service failure from an answer error. Explain whether submission happened, avoid duplicate payments and provide a safe retry or support route.

## Interruption pages

Explain why the task is interrupted, what has been saved, and a clear way to continue or get help. Avoid automatic redirects that lose context.

<Preview name="SessionExpired" locale="en" />


<div className="sdr-example-code">
<Tabs>

## Service integration

Examples use library components. Server validation, messaging, payment processing and persistence are implemented by the application. Demonstration interactions stay local and do not persist after reload. JavaScript setup is documented once in [Get started](/en/getting-started/). Accessibility details are in [the accessibility guide](/en/accessibility/).
