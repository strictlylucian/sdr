import { useState } from 'react';
import * as R from '@strictlylucian/sdr-react';

const locale = 'en';

export function ButtonExample() {
  const [saved, setSaved] = useState(false);
  return (
    <R.Cluster>
      <R.Button onClick={() => setSaved(true)}>Save application</R.Button>
      <R.Button
        variant="secondary"
        onClick={() => setSaved(false)}
      >
        Reset
      </R.Button>
      <R.Button variant="tertiary">Review application</R.Button>
      <R.Button variant="danger">Delete draft</R.Button>
      <R.Button variant="danger-secondary">Remove attachment</R.Button>

    </R.Cluster>
  );
}
~~~

## Usage

The primary variant emphasises the main action; secondary has a neutral background and tertiary has a link-like appearance. danger uses red for destructive actions; danger-secondary provides an outlined alternative. Labels describe the consequence, such as “Delete draft”. Keyboard focus and pressed states use yellow. Buttons default to type="button"; form submission uses type="submit". The application owns validation and action confirmation.



## API

| Property | Type | Required |
|---|---|---|
| `variant` | `"primary" \| "secondary" \| "tertiary" \| "danger" \| "danger-secondary" \| undefined` | No |

Native HTML, aria-* and data-* attributes are available where allowed by the component types. Component-specific properties are extracted from TypeScript when generating documentation.

## Toggle button

The toggle variant exposes state through aria-pressed. defaultPressed sets the initial value; the label stays the same when toggled.

<Preview name="ToggleButton" locale="en" />


<div className="sdr-example-code">

~~~

## Accessibility

Composition accessibility depends on labels, element semantics, focus order and application context. Library themes and behaviours are checked against the documented examples; those results do not assess the consuming service. The matrix and limitations are described in [the accessibility guide](/en/accessibility/).
