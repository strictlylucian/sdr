## Confirm a phone number

Allow pasting one-time codes and use autocomplete=one-time-code. Provide resend, expiry and a voice or assisted route. Rate limiting belongs on the server.

<TabItem label="React">


~~~tsx
import { useState } from 'react';
import * as R from '@strictlylucian/sdr-react';

const locale = 'en';

export function PhoneConfirmationExample() {
  const [done, setDone] = useState(false);
  return (
    <form
      data-sdr-pattern-demo="phone-code"
      className="sdr-stack"
      onSubmit={(event) => {
        event.preventDefault();
        const form = event.currentTarget;
        setDone(true);
        requestAnimationFrame(() =>
          form
            .closest('[data-sdr-pattern-demo]')!
            .querySelector<HTMLElement>('[data-sdr-pattern-result]')!
            .focus(),
        );
      }}
    >
      <h3>Enter the code from your text message</h3>
      <R.TextInput
        label="Security code"
        name="security-code"
        type="text"
        inputMode="numeric"
        autoComplete="one-time-code"
        pattern="123456"
        title="The test code is 123456."
        required
      />
      <div>
        <R.Button type="submit">Verify number</R.Button>
      </div>
      <R.Details summary="Have you not received a code?">
        Check that your phone number is correct. The message may take a few
        minutes to arrive.
      </R.Details>
      <p
        role="status"
        data-sdr-pattern-result
        tabIndex={-1}
        hidden={!done}
      >
        Your phone number has been confirmed.
      </p>
    </form>
  );
}
~~~

## Confirm an email address

Show the destination address and allow correction. Explain expiry and resend. Link confirmation should reach a clear success page and preserve the interrupted task.

## Service integration

Examples use library components. Server validation, messaging, payment processing and persistence are implemented by the application. Demonstration interactions stay local and do not persist after reload. JavaScript setup is documented once in [Get started](/en/getting-started/). Accessibility details are in [the accessibility guide](/en/accessibility/).
