## Create accounts

Do not require an account for a one-off task without evidence. Explain recovery, personal data use, and a route for people who cannot use the primary authentication method.

<Preview name="AccountCreation" locale="en" />


<div className="sdr-example-code">
<Tabs>
<TabItem label="React">


~~~tsx
import { useState } from 'react';
import * as R from '@strictlylucian/sdr-react';

const locale = 'en';

export function AccountCreationExample() {
  const [done, setDone] = useState(false);
  return (
    <form
      data-sdr-pattern-demo="account"
      className="sdr-stack"
      onSubmit={(event) => {
        event.preventDefault();
        const form = event.currentTarget;
        setDone(true);
        requestAnimationFrame(() =>
          form
            .closest('[data-sdr-pattern-demo]')!
            .querySelector<HTMLElement>('[data-sdr-pattern-result]')!
            .focus(),
        );
      }}
    >
      <h3>Create an account for your applications</h3>
      <R.InsetText>
        Demonstration account. Use fictional details; no real account is
        created.
      </R.InsetText>
      <R.TextInput
        label="Email"
        type="email"
        autoComplete="username"
        name="account-email"
        required
      />
      <R.PasswordCreationFields
        required
        showLabel="Show password"
        hideLabel="Hide password"
        label="Choose a password"
        hint="Use a unique password. A password manager can help."
      />
      <div>
        <R.Button type="submit">Simulate account creation</R.Button>
      </div>
      <p
        role="status"
        data-sdr-pattern-result
        tabIndex={-1}
        hidden={!done}
      >
        Example completed. No accounts were created and no passwords were
        stored.
      </p>
    </form>
  );
}
~~~

## Service integration

Examples use library components. Server validation, messaging, payment processing and persistence are implemented by the application. Demonstration interactions stay local and do not persist after reload. JavaScript setup is documented once in [Get started](/en/getting-started/). Accessibility details are in [the accessibility guide](/en/accessibility/).
