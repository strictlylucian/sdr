## Phone numbers

Use type=tel and autocomplete=tel. Accept international country codes, spaces and pasted numbers. Explain whether SMS or voice is required.

<Preview name="PhoneNumber" locale="en" />


<div className="sdr-example-code">
<Tabs>
<TabItem label="React">


~~~tsx
import { useState } from 'react';
import * as R from '@strictlylucian/sdr-react';

const locale = 'en';

export function PhoneNumberExample() {
  const [done, setDone] = useState(false);
  return (
    <form
      data-sdr-pattern-demo="phone"
      className="sdr-stack"
      onSubmit={(event) => {
        event.preventDefault();
        const form = event.currentTarget;
        setDone(true);
        requestAnimationFrame(() =>
          form
            .closest('[data-sdr-pattern-demo]')!
            .querySelector<HTMLElement>('[data-sdr-pattern-result]')!
            .focus(),
        );
      }}
    >
      <h3>Which number can we contact you on?</h3>
      <R.TextInput
        label="Phone number"
        type="tel"
        name="phone"
        autoComplete="tel"
        required
        hint="We will only call about your application. Include the country code for numbers outside Romania."
      />
      <div>
        <R.Button type="submit">Continue</R.Button>
      </div>
      <R.Link href={`/${locale}/patterns/contact-details/#variant-email`}>
        I prefer an email response
      </R.Link>
      <p
        role="status"
        data-sdr-pattern-result
        tabIndex={-1}
        hidden={!done}
      >
        Your phone number has been saved.
      </p>
    </form>
  );
}
~~~

## Email addresses

Use type=email and autocomplete=email. Let users paste. Confirm ownership with a link when required, rather than asking them to type the address twice.

## Service integration

Examples use library components. Server validation, messaging, payment processing and persistence are implemented by the application. Demonstration interactions stay local and do not persist after reload. JavaScript setup is documented once in [Get started](/en/getting-started/). Accessibility details are in [the accessibility guide](/en/accessibility/).
