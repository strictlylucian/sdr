## Error state

The error message is associated with the control through aria-describedby, and aria-invalid exposes its state. In React, error enables this presentation; the application owns validation rules and when messages appear. The HTML edition uses the same structure and CSS classes.

<Preview name="SelectError" locale="en" />


<div className="sdr-example-code">
<Tabs>
<TabItem label="React">


~~~tsx

const locale = 'en';

export function SelectErrorExample() {
  return (
    <R.Select
      error="Choose a county."
      label="County"
      name="error-county"
    >
      <option value="">Choose a county</option>
      <option value="CJ">Cluj</option>
      <option value="BV">Brașov</option>

  );
}
~~~

</TabItem>

## Disabled

The disabled attribute disables the control and excludes it from Tab navigation and submitted form data. Groups use disabled on the fieldset. A visible explanation can describe why a control is unavailable.

<Preview name="SelectDisabled" locale="en" />


<div className="sdr-example-code">
<Tabs>
<TabItem label="React">

      <option value="CJ">Cluj</option>

## Read-only

This control has no native HTML readonly attribute. The example uses SummaryList to display a fixed value. The application manages any value that must be submitted separately; disabled excludes a control from form data.

<Preview name="SelectReadOnly" locale="en" />


<div className="sdr-example-code">
<Tabs>
<TabItem label="React">


~~~tsx
import { useState } from 'react';
import * as R from '@strictlylucian/sdr-react';

const locale = 'en';

export function SelectReadOnlyExample() {
  return <R.SummaryList items={[{ key: 'County', value: 'Cluj' }]} />;
}
~~~

## Usage

Prefer radios for a small set. Do not preselect an answer without evidence.



## API

| Property | Type | Required |
|---|---|---|
| `label` | `ReactNode` | Yes |
| `hint` | `ReactNode` | No |
| `error` | `ReactNode` | No |
| `id` | `string \| undefined` | No |

Native HTML, aria-* and data-* attributes are available where allowed by the component types. Component-specific properties are extracted from TypeScript when generating documentation.



## Accessibility

Composition accessibility depends on labels, element semantics, focus order and application context. Library themes and behaviours are checked against the documented examples; those results do not assess the consuming service. The matrix and limitations are described in [the accessibility guide](/en/accessibility/).
