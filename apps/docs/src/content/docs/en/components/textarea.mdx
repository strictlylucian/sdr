## Error state

The error message is associated with the control through aria-describedby, and aria-invalid exposes its state. In React, error enables this presentation; the application owns validation rules and when messages appear. The HTML edition uses the same structure and CSS classes.

## Read-only

The readOnly prop (readonly in HTML) keeps the value visible and included in submitted form data. Text fields remain focusable and their contents can be selected and copied, but not edited. Native date and time widgets retain the browser’s navigation behaviour. Date groups and Fieldset examples apply the state to each text field.

## Usage

Do not request information already supplied elsewhere. Avoid fixed heights that clip text.



## API

| Property | Type | Required |
|---|---|---|
| `label` | `ReactNode` | Yes |
| `hint` | `ReactNode` | No |
| `error` | `ReactNode` | No |
| `id` | `string \| undefined` | No |

Native HTML, aria-* and data-* attributes are available where allowed by the component types. Component-specific properties are extracted from TypeScript when generating documentation.

## With character count

CharacterCount composes Textarea with counting for limited answers. It counts Unicode code points rather than grapheme clusters. Text is not truncated; limit validation belongs to the application and server.

<Preview name="CharacterCount" locale="en" />


<div className="sdr-example-code">
<Tabs>
<TabItem label="React">


~~~tsx
import { useState } from 'react';
import * as R from '@strictlylucian/sdr-react';
import { createInstance } from 'i18next';

// Application-owned translations; SDR only receives the formatter callback.
const i18n = createInstance();
void i18n.init({
  lng: 'en',
  initAsync: false,
  fallbackLng: false,
  resources: {
    en: {
      translation: {
        remaining_one: '{count} character remaining',
        remaining_other: '{count} characters remaining',
        over_one: 'You are {count} character over the limit',
        over_other: 'You are {count} characters over the limit',
      },
    },
  },
  interpolation: { prefix: '{', suffix: '}', escapeValue: false },
});
const formatCount = (remaining: number) =>
  i18n.t(remaining < 0 ? 'over' : 'remaining', { count: Math.abs(remaining) });

const locale = 'en';

export function CharacterCountExample() {
  return (
    <R.CharacterCount
      id="description"
      label="Describe the situation"
      name="description"
      limit={200}
      formatCount={(remaining) => formatCount(remaining)}
    />
  );
}
~~~

</TabItem>
<TabItem label="HTML">


~~~html
<div
  lang="en"
  data-sdr-theme="light"
  data-sdr-density="comfortable"
  class="sdr"
>
  <div
    data-sdr-component="character-count"
    data-sdr-limit="200"
    class="sdr-stack sdr-u-gap-2"
  >
    <div class="sdr-field">
      <label
        class="sdr-label"
        for="description"
        >Describe the situation</label
      ><textarea
        name="description"
        id="description"
        aria-describedby="description-count"
        class="sdr-textarea"
      ></textarea>
    </div>
    <p
      id="description-count"
      class="sdr-character-count"
      data-sdr-count="true"
      aria-live="polite"
      aria-atomic="true"
    >
      200 characters remaining
    </p>
  </div>
</div>
~~~

## Accessibility

Composition accessibility depends on labels, element semantics, focus order and application context. Library themes and behaviours are checked against the documented examples; those results do not assess the consuming service. The matrix and limitations are described in [the accessibility guide](/en/accessibility/).
